# Model Facts — gpt-image-2

이 문서는 gpt-image-2의 정확한 능력치·제약·파라미터·가격 경제학을 정리한 지식 레이어다. 모델 선택이 불확실하거나, 사이즈/파라미터 유효값을 확인해야 하거나, 가격·품질 트레이드오프를 판단해야 할 때 로드한다. 호출 코드 샘플과 Codex CLI 라우팅은 `references/api-and-codex-routes.md`를 참조한다.

## 모델 개요 & 수명주기

**Documented fact (2026-07-09 기준 공식 문서 검증):** `gpt-image-2`는 2026-04-21 출시된 현행 프로덕션 기본 모델이다. 별칭(alias) `gpt-image-2`와 스냅샷 `gpt-image-2-2026-04-21` 두 형태로 제공된다. 자동 업데이트가 필요하면 alias를, 회귀(regression) 안정성이 필요하면 스냅샷을 고정해서 쓴다.

| 모델 | 현재 역할 | 수명주기 |
|---|---|---|
| `gpt-image-2` | 현행 기본 생성/편집 모델 | alias 또는 스냅샷 `gpt-image-2-2026-04-21` |
| `gpt-image-1.5` | 이전 세대 | Deprecated, API 제거 예정 **2026-12-01** |
| `gpt-image-1` | 이전 세대 | Deprecated, API 제거 예정 **2026-10-23** |
| `gpt-image-1-mini` | 저비용 경량 변형 | Deprecated, API 제거 예정 **2026-12-01** — 신규 의존 시작 금지, `gpt-image-2`의 `quality="low"`로 대체 테스트 |
| `dall-e-3`, `dall-e-2` | 레거시 마이그레이션 지식용 | 2026-05-12 API에서 이미 제거됨 |

**Production heuristic:** 신규 작업은 기본적으로 `gpt-image-2`로 시작한다. Deprecated 모델을 유지하는 유일한 이유는 마이그레이션 비교 측정뿐이며, 단가표가 더 싸 보인다는 이유만으로 선택하지 않는다.

GPT-Image-1.5 대비 gpt-image-2의 핵심 변화(커뮤니티 활용 가이드 기준): O-시리즈 추론(reasoning)을 이미지 생성 파이프라인에 통합해 "생성 전에 생각"하는 구조를 취하고, 고밀도 텍스트·CJK(한중일) 다국어 렌더링·긴 멀티파트 프롬프트 추종성이 크게 개선되었다. 색감도 GPT-Image-1.5의 따뜻한 톤 편향에서 중립적인 재현으로 바뀌었다.

**Thinking 모드(ChatGPT 제품 레벨 기능 — API 레벨 기능이 아님):** ChatGPT Plus/Pro/Business에서 Thinking을 켜면 웹 검색을 수행하고, 한 요청 안에서 **최대 8장까지 인물·환경 일관성을 유지한 개별 이미지**를 동시 생성할 수 있다. 이는 ChatGPT UI/제품 특유의 동작이며 순수 Images API 호출 계약에는 별도 문서화된 "Thinking" 파라미터가 없다는 점에 유의한다. API 레벨에서 유사한 다중 컷 일관성을 얻으려면 Responses API의 `previous_response_id` 기반 멀티턴 편집 체인을 쌓는 방식을 쓴다. 8장 동시 생성 워크플로우와 3×3 그리드 대비 개별 시퀀스 생성 전략의 실전 활용법은 `multi-shot.md`를 상호참조한다.

**접근 경로별 요약(커뮤니티 활용 가이드 §1):** ChatGPT 무료/유료 사용자는 기본 Images 2.0 기능을 쓸 수 있고, Plus/Pro/Business 사용자는 Thinking 모드(웹 검색 + 다중 이미지 일관 생성)를 켤 수 있다. API(`gpt-image-2`)는 토큰 기반 과금이며 품질·해상도에 따라 단가가 달라진다 — 이 문서의 가격 섹션은 API 경로 기준이다.

## 하드 제약

**Documented facts, Images API 기준, 2026-07-09 검증:** `size="auto"` 또는 다음 네 조건을 모두 만족하는 임의 해상도를 받는다.

| 제약 항목 | 규칙 |
|---|---|
| 최대 변 길이 | 3840px 미만 |
| 픽셀 단위 | 가로·세로 모두 16의 배수 |
| 종횡비 | 긴 변:짧은 변 최대 3:1 |
| 총 픽셀 수 | 655,360 ~ 8,294,400 px |

커뮤니티 활용 가이드(§8.1)도 동일한 네 조건을 재확인하며, 이를 어기면 API 오류가 발생한다고 명시한다(예: `1921x1080`처럼 16의 배수가 아니면 거부). 두 소스가 수치까지 정확히 일치해 신뢰도가 높다.

정확히 유효한 사이즈 값의 화이트리스트(권장 6종 조합 등 프롬프트에 바로 쓸 수 있는 목록)는 `core-grammar.md`의 사이즈 화이트리스트를 상호참조한다. 이 문서에서는 제약 "규칙"만 다루고 구체적 프리셋 나열은 core-grammar.md에 위임한다.

**Production heuristic:** 2,560×1,440 총 픽셀을 넘는 해상도는 공식 문서상 "실험적(experimental)"으로 표시되며 결과 변동성이 크다. 안정적인 고품질 결과가 필요하면 2048×2048 이하에서 작업하고, 그 이상은 반드시 사전 테스트 후 프로덕션에 반영한다. 정사각형이 대체로 가장 빠르다.

**Responses API `image_generation` 툴의 스키마는 Images API보다 좁다.** `auto`, `1024x1024`, `1024x1536`, `1536x1024`만 지원한다. Images API에서 쓴 임의 해상도를 그대로 Responses 툴 호출에 복사하지 않는다.

### 투명 배경 미지원 (negative knowledge)

**Documented fact:** `gpt-image-2`는 현재 투명 배경을 지원하지 않는다. `background="transparent"`를 보내지 않는다. `background="opaque"` 또는 `"auto"`로 생성하고, 알파 채널이 필요하면 대비가 뚜렷한 매트(matte) 배경 위에 생성한 뒤 다운스트림 배경 제거 프로세스를 별도로 돌린다. 구형 GPT Image 모델(1, 1.5, mini)은 투명 출력을 지원했지만 이미 deprecated 상태이므로, 투명 배경만을 이유로 구형 모델에 새로 의존하지 않는다.

### 기타 negative knowledge

- `input_fidelity` 파라미터는 gpt-image-2에서 비활성/무의미하다. gpt-image-2는 모든 이미지 입력을 기본적으로 고정밀(high fidelity)로 처리하므로 이 파라미터를 생략한다. 단, 일부 엔드포인트 스키마 문서가 여전히 "GPT Image 1, 1.5 and later"라는 문구로 이를 언급하는 문서 간 불일치가 있으니, 최신 코어 이미지 가이드 쪽(생략)을 따른다.
- 전용 이미지 작업 폴링(job ID) 엔드포인트는 현재 문서화되어 있지 않다. 스트리밍(SSE, `partial_images`)과 Batch 지원/가격은 문서화되어 있지만, 비동기 대량 처리를 설계하기 전에 Batch 엔드포인트 계약을 별도로 재확인해야 하며, 존재하지 않는 폴링 API를 임의로 가정하지 않는다.
- 마스크는 프롬프트 기반 안내이며 윤곽을 픽셀 단위로 정확히 따르지 않을 수 있다. 다중 입력 시 마스크는 첫 번째 이미지에만 적용된다.
- Responses의 top-level `model`(예: `gpt-5.5` 등 현행 메인라인 모델)과 `tools[].model="gpt-image-2"`는 서로 다른 선택이다. `gpt-image-2`를 top-level `model`로 넘기지 않는다 — 툴 레벨 선택자를 생략하면 스키마의 구형 기본값으로 조용히 폴백할 수 있다.

### Provenance — C2PA/SynthID (Documented fact)

API로 생성한 gpt-image-2 이미지에는 C2PA 메타데이터와 임베디드 SynthID 워터마크가 함께 포함된다. 다만 C2PA 메타데이터는 후처리로 제거될 수 있고 SynthID 신호는 변환(리사이즈, 압축, 포맷 변경)을 거치며 열화될 수 있다 — 두 신호 중 하나가 없다고 해서 그 이미지가 사람이 만든 것이라는 증거는 아니다. 검증기는 "OpenAI 출처 가능성"만 표시할 뿐 사실 정확성·수정 여부·소유권·맥락의 정확성은 보증하지 않는다.

**Production heuristic:** 원본 생성 바이트와 메타데이터를 보존하고, 불필요한 트랜스코딩을 피하며, 내부 생성 원장(ledger)에 요청/응답 ID를 기록한다. Provenance 신호를 "사실 확인 인증서"로 취급하지 않는다.

## 파라미터 계약

| 파라미터 | 유효값 | 비고 |
|---|---|---|
| `size` | `auto` 또는 하드 제약을 만족하는 임의 해상도 (Responses 툴은 `auto`/`1024x1024`/`1024x1536`/`1536x1024`로 제한) | 위 하드 제약 표 참조 |
| `quality` | `low` / `medium` / `high` / `auto` | 아래 품질 경제학 참조 |
| `output_format` | `png`(기본) / `jpeg` / `webp` | jpeg·webp는 `output_compression`(0~100) 지정 가능, 문서상 jpeg가 png보다 빠름 |
| `background` | `opaque` / `auto` | `transparent` 미지원 |
| `moderation` | `auto`(표준) / `low`(완화, 정책 자체를 끄는 것은 아님) | |
| `n` | 1~10 (기본 1) | 승인된 샘플/배치 계획만큼만 생성 |
| `stream` + `partial_images` | `partial_images` 0~3 | partial 1장당 이미지 출력 토큰 100개 추가 과금, 최종 이미지 QA 대체 수단 아님 |
| 입력 이미지(edits) | PNG/WebP/JPEG, 파일당 50MB 미만, 최대 16장 | Responses에서는 URL, base64 data URL, `purpose="vision"` Files API ID도 가능 |
| `mask` | PNG, 4MB 미만, 알파 채널 포함, 첫 번째 입력 이미지와 동일 해상도 | 완전 투명 영역이 편집 허용 구역 |

복잡한 프롬프트는 최대 2분까지 걸릴 수 있으므로 클라이언트 타임아웃과 레이트리밋을 명시적으로 처리한다. **Documented rate limits (2026-07-09 검증):** Free 미지원; Tier 1 `100,000 TPM / 5 IPM`; Tier 2 `250,000 / 20`; Tier 3 `800,000 / 50`; Tier 4 `3,000,000 / 150`; Tier 5 `8,000,000 / 250`. 티어는 지출에 따라 변동되므로 모델 페이지에서 재확인한다.

### 실패 클래스별 처리 (파라미터 계약의 일부)

- `429`/`5xx`는 지수 백오프 + jitter로 재시도하고 레이트리밋 헤더와 request ID를 로그에 남긴다.
- `image_generation_user_error`는 요청 자체를 바꾸지 않는 한 자동 재시도하지 않는다.
- `error.code == "moderation_blocked"`는 별도 분기 처리한다. `moderation_details`는 선택적이며 `input`/`output`/`unknown` 단계와 대략적 카테고리만 제공하는 디버깅용 정보다 — 최종 사용자에게는 일반화된 메시지를, 로그에는 안전한 수준의 상세만 남긴다. 동일 요청을 우회 표현으로 재시도하지 않는다.

## 데이터 보존 & 상업적 이용 (요약)

**Documented fact:** API 데이터는 고객이 명시적으로 옵트인하지 않는 한 OpenAI 모델 학습에 사용되지 않는다. 기본적으로 어뷰징 모니터링 로그는 최대 30일 보관될 수 있다. `/v1/images/generations`, `/v1/images/edits`는 현재 문서상 애플리케이션 상태 보존이 없어 ZDR(Zero Data Retention) 승인 대상이 될 수 있다. `store=false`만으로는 승인된 ZDR과 동일하지 않다.

OpenAI 비즈니스 약관상 고객·OpenAI 사이에서는 법이 허용하는 범위 내에서 고객이 입력 권리를 유지하고 산출물을 소유하지만, 이는 산출물의 저작권 성립·비침해·상표 무결·사실 정확성·독점성을 보장하지 않는다. 상업적 납품 전에는 유사 로고/트레이드 드레스 검색, 라이선스·동의서 확인, 출처 보존, 필요 시 법률 검토를 거친다.

gpt-image-1.5는 텍스트/이미지 입력 단가가 gpt-image-2와 동일하지만 이미지 출력이 오히려 더 비싸다 — 단가표만 보고 구형 모델을 선택할 이유가 없다. `gpt-image-1-mini`는 단가가 눈에 띄게 낮지만 deprecated이며 2026-12-01 API 제거 예정이므로, 저비용이 목적이면 `gpt-image-2`의 `quality="low"`로 대체 검증하는 편이 안전하다.

**Production heuristic — draft low → final high 전략:** 초안 단계에서 `quality="low"`로 구도·레이아웃·컨셉을 확정한 뒤, 승인된 후보만 `quality="high"`로 최종 재생성하면 전체 비용을 **60~80% 절감**할 수 있다(커뮤니티 활용 가이드 §8.2). Low는 대량 생성·빠른 아이데이션·단순 배경/오브젝트에 적합하고, 작은 텍스트·정밀 인물·edit 작업에는 medium 이상을 쓴다. High quality가 모순된 프롬프트나 부정확한 레이아웃 지시를 자동으로 교정해주지는 않으므로, 스펙 자체를 먼저 고친다.

**사이즈·품질이 텍스트 정확도에 미치는 영향(1줄):** 작고 촘촘한 텍스트, 인포그래픽 내 고밀도 텍스트는 `quality="low"`에서 오타·왜곡 위험이 커지므로 medium 이상, 특히 고밀도 텍스트/여러 폰트가 섞이면 high를 쓴다 — 정확한 텍스트 프롬프팅 기법은 `text-in-image.md`를 상호참조한다.

## 모델 선택 가이드

gpt-image-2가 아닌 다른 모델을 고려할 상황(각 공식 문서 기준 2026-07-09 검증):

| 모델 | 강점 1줄 | gpt-image-2 대신 선택하는 경우 |
|---|---|---|
| **Midjourney (V8.1/V7/Niji 7)** | Omni Reference 기반 스타일화된 아트, 강한 미학적 기본값 | 회화적/일러스트 스타일 우선, 공식 API 없이 웹·Discord 수동 워크플로만 허용되는 환경 |
| **Google Gemini 이미지 (NanoBanana 2 계열)** | 자연스러운 피부 질감·미학, Interactions API 기반 대화형 편집 | 사실적 인물 질감이 최우선이거나 Google Search 그라운딩이 필요한 사실 기반 이미지 |
| **ByteDance Seedream (5.0 등)** | 다중 레퍼런스 퓨전(최대 10~14장), grouped/streamed 출력 | 여러 레퍼런스 이미지를 한 번에 합성하거나 세트 단위 그룹 출력이 필요한 경우 |

**종합 판단(커뮤니티 활용 가이드 §5):** gpt-image-2는 복잡한 레이아웃·고밀도 텍스트·긴 멀티파트 프롬프트 추종에서 우위가 뚜렷하고, NanoBanana 2는 여전히 자연스러운 피부 질감과 단순 구도의 미학적 완성도에서 강점을 유지한다. Midjourney·Seedream은 각각 스타일화/레퍼런스 융합이라는 별도 축의 강점을 가지므로, "정확한 지시 추종 + 텍스트/레이아웃"이 목표면 gpt-image-2, "미학적 스타일 탐색"이면 Midjourney, "사실적 피부/대화형 편집"이면 Gemini, "다중 레퍼런스 합성"이면 Seedream을 우선 검토한다.

## 출처 신뢰도

- **Documented fact**: OpenAI 공식 문서(모델 페이지, 이미지 생성 가이드, 가격 페이지, deprecations 페이지 등)가 현재 명시하는 동작. 이 문서에서 사이즈 제약, 파라미터 유효값, 가격표, 레이트리밋, 투명 배경 미지원은 모두 이 등급이다.
- **Production heuristic**: 문서화된 동작과 프로덕션 리스크에서 도출한 실무 권장사항이지 API가 보장하는 계약이 아니다. draft low → final high 절감 전략, quality 선택 기준, 2K 초과 해상도 주의 등이 여기 속한다.
- **Inference / 커뮤니티 검증**: 공식 문서에 없는 추론이거나 실전 사용자 커뮤니티에서 반복 확인된 관찰이다. Thinking 모드의 "최대 8장 일관 생성"은 ChatGPT 제품 UI 관찰에 기반한 커뮤니티 활용 가이드의 서술이며, 순수 API 계약 문서에는 이에 대응하는 파라미터가 별도 문서화되어 있지 않다 — 실제 워크로드에서 검증 후 사용한다.

**두 주요 소스 간 대조 결과:** 사이즈 하드 제약 4항목과 quality×사이즈 가격표(1024×1024/1024×1536/1536×1024 × low/medium/high 9칸)는 두 소스가 수치까지 정확히 일치하며, gpt-image-2의 스냅샷 식별자(`gpt-image-2-2026-04-21`)와 커뮤니티 가이드가 밝힌 출시일(2026-04-21)도 서로 부합해 상호 검증된다. 유일한 불일치는 커뮤니티 가이드가 부가적으로 언급한 "텍스트 출력 $10/M" 토큰 단가로, 공식 문서의 gpt-image-2 가격표에는 별도 텍스트 출력 항목이 없다(이미지 모델은 텍스트를 산출물로 반환하지 않으므로 실질적 과금 항목이 아닐 가능성이 높다). 이 문서는 공식 문서 쪽의 5개 항목(텍스트 입력, 이미지 입력 표준/캐시, 이미지 출력, Batch 3종)만 신뢰 가능한 가격표로 채택하고, 텍스트 출력 단가는 표에서 제외했다.
